# python-mcp-bootstrap v0.1.1

Patch release focused on behavior fixes and verifiable release artifacts. No
packaging shape changes: still a pure-Python, dependency-free wheel with the
same public contract and Python floor.

## Highlights

- Explicit `--python` interpreters are verified: `verify_import` is checked on
  every interpreter branch, and one that cannot import the app reports
  `verify_import_failed` (exit `5`) instead of handing off.
- An interpreter that cannot be started returns a JSON `exec_failed` report
  (exit `8`) rather than a traceback.
- `BootstrapSpec` is genuinely immutable: list inputs are copied to tuples and
  validated at construction; `required` rejects invalid shapes with
  `ValueError`.
- Credential redaction covers Basic/Bearer/Token/Digest authorization headers,
  URL passwords containing `/`, and prefixed/suffixed credential keys such as
  `AWS_SECRET_ACCESS_KEY`.
- `install_args` reject system-modifying flags (`--system`,
  `--break-system-packages`), `file:` URLs, drive-relative Windows paths, and
  value-taking long flags not passed as `--flag=VALUE`.
- A failed provisioning run on a too-old uv now explains that upgrading uv (or
  passing `--python`) is the fix.

## Release integrity

- `v0.1.1` is an annotated tag. The publish workflow rebuilds the wheel and
  sdist from the tagged tree with the pinned build backend, writes
  `SHA256SUMS`, uploads the assets, attests build provenance, signs every
  artifact with Sigstore, re-runs the release gate over the published assets,
  and only then publishes to PyPI with OIDC trusted publishing.
- `v0.1.0` predates the attestation step: it has `SHA256SUMS` and Sigstore
  signatures, but no `provenance.intoto.jsonl`.
- Tags are unsigned. Artifact signatures and provenance live in the release
  assets; a tag is not a signature.

## Honest limits

- Path checks stay lexical: they do not resolve symlinks, so a symlink inside
  the project can still point outside. The consumer owns that boundary.
- Concurrent first runs against one project are not supported; there is no lock
  around the `.venv` move or the provisioning steps.
- Still alpha (`0.1.x`): the contract and exit codes are treated as the public
  API and follow semantic versioning.
