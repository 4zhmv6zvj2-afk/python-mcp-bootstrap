# python-mcp-bootstrap v0.1.4

Re-release of 0.1.3 under a new version number. The code is identical; only
the version string differs.

## Why 0.1.4 and not 0.1.3 on PyPI

PyPI permanently blocks the `0.1.3` filenames: a file with those names was
previously uploaded and deleted outside this repository's release pipeline,
and PyPI does not permit a filename to be reused after deletion. The `v0.1.3`
GitHub release remains available as a GitHub-only release with verified assets
(wheel, sdist, `SHA256SUMS`, three Sigstore bundles and build provenance), but
it was never published to PyPI. This release is the installable equivalent.

## What changed in 0.1.3 (included here)

- The `v0.1.2` sdist could not run its bundled test suite. The sdist now ships
  `requirements-ci.txt` and `requirements-build.txt`, repository-only workflow
  tests skip when `.github/` is absent, and CI runs the extracted-sdist suite.
- Provisioning uses `uv pip install --python <venv python> <install_args>`, so
  a trailing consumer-supplied flag cannot swallow the interpreter argument.
- `publish.yml` verifies build provenance for the sdist as well as the wheel.
- CI builds with the pinned backend (`--no-isolation`); `release-gate.yml` no
  longer waits for assets that already exist.
- README and CONTRIBUTING corrections for the `v0.1.2` provenance wording and
  the macOS CI schedule.

## Release integrity

- `v0.1.4` is an annotated tag. Assets are built once by `prepare-release`,
  attached to a draft, verified, and only then published; the release is
  immutable with seven assets: wheel, sdist, `SHA256SUMS`, three
  `.sigstore.json` bundles, and `provenance.intoto.jsonl`.
- `publish.yml` verifies checksums, the full release gate, and both artifact
  attestations before publishing to PyPI last with OIDC trusted publishing.
