# python-mcp-bootstrap v0.1.3

Patch release. The headline fix is that the shipped sdist now passes its own
bundled test suite.

## Fixed

- **The `v0.1.2` sdist could not run its tests.** It omitted
  `requirements-ci.txt` and `requirements-build.txt`, and
  `tests/test_workflows.py` read `.github/workflows` even outside a repository
  checkout, so pytest inside the extracted archive failed. This sdist ships
  both pinned requirement files, skips repository-only workflow tests when
  `.github/` is absent, and CI now runs the extracted-sdist suite so the
  regression cannot return. `v0.1.3` is the first sdist whose bundled tests
  pass; upgrade from the `v0.1.2` sdist.
- **Install-argument ordering.** Provisioning now runs
  `uv pip install --python <venv python> <install_args>`. Previously the
  interpreter flag came after consumer-supplied arguments, so a trailing
  value-taking flag could swallow it. Validation of `install_args` is
  unchanged.

## Pipeline

- `publish.yml` verifies build provenance for the sdist as well as the wheel.
- CI builds wheel and sdist with `--no-isolation` using the pinned backend,
  matching the release build.
- `release-gate.yml` no longer waits for assets that existed before
  publication.

## Docs

- README and CONTRIBUTING corrections for the `v0.1.2` provenance wording and
  the macOS CI schedule.

## Release integrity

- `v0.1.3` is an annotated tag. Assets are built once by `prepare-release`,
  attached to a draft, verified, and only then published; the release is
  immutable with seven assets: wheel, sdist, `SHA256SUMS`, three
  `.sigstore.json` bundles, and `provenance.intoto.jsonl`.
- `publish.yml` verifies checksums, the full release gate, and both artifact
  attestations before publishing to PyPI last with OIDC trusted publishing.
